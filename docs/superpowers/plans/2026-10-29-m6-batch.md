# M6 Batch Rendering, QA and Upload Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One GitHub Actions job per video: build the spec, render, run automated QA, and (when asked) upload as a scheduled private video, idempotently, with a ledger that matches YouTube Studio. This is the path from committed content to scheduled uploads.

**Architecture:** Three Python modules (`qa.py`, `ledger.py`, a complete `upload.py`) behind the existing CLI (`chesscode qa|ledger|upload`), plus `batch.yml` (matrix, `workflow_dispatch`) and `collect.yml` (`workflow_run`). Scripts and analysis are committed (`content/scripts/`, `content/analysis/`), so a batch job never calls an LLM or Stockfish. The voice stage calls ElevenLabs with the repo secret; its audio cache is kept with `actions/cache`. Vision QA (contact sheets, thumbnails) needs a model, which Actions does not have, so jobs produce the sheets and the main session's `qa-frames` agent reviews them locally after `collect` (a video uploads only after automated checks pass; owner reviews in Studio while it sits scheduled, spec 12).

**Tech Stack:** Python 3.12, google-api-python-client, imageio-ffmpeg/ffprobe, Remotion CLI 4.0.539, GitHub Actions.

**Spec:** `docs/SPEC.md` sections 9 (workflows, job steps, matrix, secrets, batching), 10 (upload call details, quota, idempotency, description, Shorts), 12 (automated per-video checks, owner review). Existing code to extend, not replace: `pipeline/chesscode/upload.py` (`build_body`, `check_publish_at`, `with_ccid_footer`, `find_existing`, `upload_video`), `auth.py` (`load_credentials`, env secrets), `audio.measure`, `stages/emit.validate`, `calendar.py`, `runner.py`.

## Global Constraints

- Never upload twice: `ccid: <video_id>` footer; check `data/upload_log.csv`, then the channel's uploads playlist, before every insert and after any ambiguous failure.
- Refuse `publishAt` in the past or < 2 h ahead. `privacyStatus: private`, `selfDeclaredMadeForKids: false`, `containsSyntheticMedia: false` (config), `categoryId` 20 (config `config/youtube.yaml`), `defaultLanguage` and `defaultAudioLanguage` from the spec.
- Resumable upload, retry 5xx/network with exponential backoff, max 5 tries. After insert: `thumbnails.set`, then `playlistItems.insert`; a failure there leaves the video scheduled and is fixed by `chesscode upload --repair`.
- Stop at 60 uploads per Pacific day (quota pool); a stopped video is `deferred`, not failed.
- Secrets only from env (`YOUTUBE_*`, `ELEVENLABS_API_KEY`); never printed. Public repo: never upload MP4s as artifacts; artifacts < 5 MB (result.json, thumb.png, contact sheet).
- A video that fails any automated check is `failed_qa` and never uploaded; no override flag.
- `batch.yml` is `workflow_dispatch` only (inputs `batch_id`, `video_ids` JSON list, `upload` true/false); `fail-fast: false`, `max-parallel: 16`, `timeout-minutes: 300`, `concurrency: video-${{ matrix.video_id }}`; permissions `contents: read`. `collect.yml` needs `contents: write` to commit the ledger.

## Review Focus

1. A job that times out mid-upload, then a rerun of the same video → must find the earlier upload by `ccid` and skip, not insert twice.
2. Two batches dispatched with an overlapping video id → the concurrency group serialises them; the second sees the ledger/playlist entry and skips.
3. Silence check vs planned pauses: the 900 ms reaction gaps and the 20 s outro are planned silence, not dead air.
4. A Short (1080×1920, ≤ 175 s) and a Hindi long-form go through the same QA with their own expected size/duration.
5. The ledger CSV commit in `collect.yml` racing a second `collect` run → rebase-and-retry, never lose rows.

### Task 1: `qa.py` automated checks

**Files:** Create `pipeline/chesscode/qa.py`, `config/qa.yaml` (extend); Test `pipeline/tests/test_qa.py`

**Interfaces:**
- `run_checks(spec_dir: Path, mp4: Path, thumb: Path) -> dict` returns `{"video_id", "passed": bool, "checks": [{"name", "passed", "detail"}], "contact_sheet": str, "thumb_small": str}` and writes `qa.json` into `spec_dir`.
- Checks (spec 12 table): `spec_valid` (`emit.validate` on `video_spec.json`), `moves_real` (SAN guard re-run on the committed script against the spec's plies + engine lines), `mascot_lines` (length caps and no repeats inside the video; the rules check already ran when the script was made), `audio_levels` (`audio.measure` on each narration segment file: -14 ± 1 LUFS, TP ≤ -1 dBTP), `dead_air` (ffmpeg `silencedetect=n=-45dB:d=2.5` on the MP4, ignoring intervals inside planned gaps from `timeline.json` and the outro), `black_frames` (`blackdetect=d=0.1`, ignoring the first and last 0.2 s), `file_format` (ffprobe: h264, yuv420p, AAC, width/height/fps from the spec, duration = `duration_ms` ± 1 frame).
- Contact sheet: frames at every beat `at_ms + 400` and every 30 s, tiled 4 columns at 480 px wide → `contact.jpg`; thumbnail downscaled to 320×180 → `thumb_320.png`.
- `chesscode qa --video <id> --mp4 <path> --thumb <path>` exits 1 when `passed` is false.
- [ ] Tests with tiny generated media (ffmpeg lavfi): a silent 3 s gap outside planned pauses fails `dead_air`, the same gap inside a planned gap passes; a black 1 s segment fails `black_frames`; wrong fps fails `file_format`; a narration file at -18 LUFS fails `audio_levels`.

### Task 3: complete `upload.py`

**Files:** Modify `pipeline/chesscode/upload.py`, Create `config/youtube.yaml`; Test `pipeline/tests/test_upload.py` (extend)

**Interfaces:**
- `config/youtube.yaml`: `category_id: 20`, `contains_synthetic_media: false`, `daily_cap: 60`, `playlists: {legendary_games: <id or null>, ...}` (null = created once, public, titled from the series name, by `chesscode upload --create-playlists` run locally before Batch 1; the ids are committed).
- `upload_from_spec(client, spec_dir: Path, ledger_path: Path, now: datetime) -> dict` (`result.json` shape: `{video_id, status, youtube_id, publish_at}`): reads `video_spec.json`, `out.mp4`, `thumb.png`, `qa.json`; refuses unless `qa.passed`; ledger then uploads-playlist dedupe; guard; resumable insert with backoff (max 5); `thumbnails.set`; `playlistItems.insert` into the series playlist; Pacific-day cap from the ledger → `deferred`.
- `chesscode upload --video <id> [--repair]`: `--repair` re-runs thumbnail + playlist steps for a ledger `scheduled` video whose follow-ups failed.
- [ ] Tests (fake client): existing ccid → skipped with the existing id; timeout on insert then retry finds the upload → no second insert; publishAt 1 h ahead refused; cap reached → deferred; thumbnail failure → `scheduled` with `needs_repair: true`; Shorts get `#Shorts` in the description.

### Task 4: `batch.yml` and `collect.yml`

**Files:** Create `.github/workflows/batch.yml`, `.github/workflows/collect.yml`, `pipeline/chesscode/batch.py`; Test `pipeline/tests/test_batch_workflow.py` (YAML structure)

- `batch.py`: `chesscode batch --video <id> [--upload]` runs one video end to end on the runner: `run --until emit` → `npx remotion render <StudioVideo|ShortsVideo> <spec>/out.mp4 --props=<spec>/video_spec.json --public-dir=<spec> --codec=h264 --crf=18 --x264-preset=veryfast` → `npx remotion still Thumbnail <spec>/thumb.png …` → `qa` → upload if asked → `result.json` with `render_seconds` and `qa_passed`. Exit 0 even on `failed_qa` (the status is in result.json); exit 1 only on crashes.
- `batch.yml` job steps (spec 9): checkout; Python 3.12 + Node 22; `actions/cache` for `remotion/node_modules`, Chrome Headless Shell, and the TTS cache directory (key: hash of `content/scripts/**` + `config/models.yaml`); Remotion Linux deps + `npx remotion browser ensure`; `chesscode auth check` when `upload`; `chesscode batch`; upload artifact `result-<id>` (result.json, thumb_320.png, contact.jpg; < 5 MB).
- `collect.yml` (`workflow_run` of batch, completed): download all `result-*` artifacts, append rows to `data/upload_log.csv`, write a run summary table (video, status, publish_at, QA, render minutes), write `docs/review/<batch_id>.md` with thumbnails/contact sheets linked from the run, commit with rebase-and-retry (3 tries).
- [ ] Test parses both YAMLs and asserts the matrix/concurrency/permissions/timeout settings and that no step uploads `*.mp4`.
