# M3 Owner Content (games.yaml + line banks) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Draft everything the owner must approve in M3: a `content/games.yaml` of 70+ evergreen games with verified PGNs and real beat notes, and `content/lines/{en,hi}.yaml` line banks (25 lines per beat type per language), plus one review page for the owner.

**Architecture:** PGNs are facts and live in `content/pgn/<slug>.pgn` (committed, `source: local`), or are fetched from Lichess (`source: lichess`) for games played or broadcast there. Every PGN is checked by a script (`scripts/check_pgns.py`) before it enters `games.yaml`. Beat notes come from running the real pipeline (`--until beats`) on each game, never from memory. Line banks are written by an Opus subagent, checked by `line-checker` (Haiku) plus a deterministic word-count/blocklist test, then reviewed by the owner.

**Tech Stack:** Python 3.12, python-chess, PyYAML, Stockfish 18 via `STOCKFISH_PATH`, existing `chesscode` pipeline stages.

**Spec:** `docs/SPEC.md` sections 4 (game sourcing rules), 8 (humor, joke rules, line bank), 11 (series, calendar). Roadmap: `docs/ROADMAP.md`.

## Global Constraints

- Evergreen only: no game whose interest depends on an event still running (spec 4).
- Game moves are facts; PGN sources are noted per game (`source_note`). Lichess exports are CC0; other databases are used for move data only. Never paste a PGN typed from memory: each must come from a downloaded database file or API, and the downloaded URL goes in `source_note`.
- At least 70 games, about 18 per series: `legendary_games`, `indian_chess_heroes`, `opening_explained`, `blunder_hall_of_fame`.
- Tiers: first 13 games in file order `tier: floor`, next 13 `tier: target`, rest `tier: spare`. Floor and target are each ordered so the series rotate (no series in more than two consecutive weeks); default cycle legendary, indian, opening, blunder.
- No two entries share a game (same players + date + moves).
- Existing `games.yaml` keys stay (`game_no, series, tier, source, source_id, pgn_file, white_country, black_country, notes`). New keys: `title_hint` (one line, the hook), `opening` (Opening Explained only: the opening name as in `content/openings/*.tsv`), `beats` (list of `"<type>@<move>"` from the pipeline), `source_note`.
- Joke rules (spec 8) verbatim: about the move, never the person (nationality, age, gender, rating); <= 8 words EN, <= 10 words HI; Hindi = natural spoken Hindi with chess terms in English; no profanity, slurs, politics, religion, sexual content, dated memes. Running gags: Pyaada wants promotion; distrusts the h-pawn; every rook lift is "too aggressive".
- Line bank format (read by `pipeline/chesscode/stages/script.py::select_bank_line`): a mapping `beat_type -> list[str]` for all 12 beat types in `config/beats.yaml` `priority`.

## Review Focus

1. A legal but wrong PGN (wrong move order from a bad source) → `check_pgns.py` cross-checks result, move count and final position with a second source where one exists; owner sees the source per game.
2. Hindi lines over 10 words when counted on spaces (the pipeline counts `split()`) → test counts the same way.
3. A line reused across beat types (repeats within one video) → test: all lines unique per language.
4. A game whose pipeline run finds fewer than 4 beats (dull long-form) → flagged `spare`, not floor.
5. Series rotation broken by file order → test using `pipeline/chesscode/calendar.py::schedule` on the draft.
