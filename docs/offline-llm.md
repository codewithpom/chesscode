# Writing scripts without an API key

There is no `ANTHROPIC_API_KEY` (owner, Oct 28). `config/models.yaml` has `provider: auto`, so the pipeline uses the offline provider until a key is set. Every guard still runs: the JSON schema, the SAN guard, specificity, script length, key-moment word counts and mascot-line rules.

## Loop per video (local machine)

1. Run `python -m chesscode run --video <id> --until script`. If no answer exists yet, the stage stops with `no answer yet; request written to build/llm_requests/<key>.json`.
2. An agent reads the request. It holds `system`, `user` (the game facts as JSON), `schema` and `answer_path`.
   - The agent writes only JSON that matches `schema` to `answer_path` (under `build/llm_answers/`).
   - Script requests come from the `script`/`script_hi` model keys. Line-check requests (`checks`) return `{"bad": [beat ids]}`.
3. Rerun step 1. A regeneration (the SAN guard, length, key moments, line check) writes a new request with the error in its `user` text. Answer it the same way, and repeat until the stage passes.
   - An invalid answer stops the stage with the answer's path and keeps the request.
4. On success, the final script is also written to `content/scripts/<video_id>.json`. **Commit that file.** Batch runs on Actions replay it: they re-check the schema, moves and line length, and never call a model.

Titles: with no cheap model, `metadata` takes the script's first valid title, so the script lists its titles best first.

The request and answer files in `build/` are transient and git-ignored. Their keys depend on the exact prompt, which depends on local engine output and line history, so only `content/scripts/` is the durable record.

When a key exists: set `ANTHROPIC_API_KEY` (or `provider: anthropic`), and scripts are generated by the API and committed to `content/scripts/` in the same way.
